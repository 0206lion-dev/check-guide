## 1. MVP 구현 범위

단일 페이지 웹 애플리케이션(입력부 + 결과부)으로 구현했다. 로그인 없이 URL 접속 즉시 사용 가능하며, 규칙 기반 판정 엔진이 위험 신호 탐지 → 유형 판정 → 확인 대상 매핑까지 전부 수행하고, 그 위에 생성형 AI 보조 레이어(상황 요약, 유형 보정)를 얹었다. 판정과 확인 경로 안내는 금융감독원 소비자경보 198건을 직접 수집·정리한 정적 데이터에 근거한다. 검증용 시나리오 3종은 AI 응답을 사전 생성해 캐시해뒀다.

| 구현 범위 | 내용 |
|---|---|
| 프론트엔드 | 정적 HTML/CSS/JS 단일 페이지(`index.html`, `style.css`, `app.js`), 빌드 도구 없음 |
| 규칙 기반 판정 엔진 | 위험 신호 탐지(데이터 기반 23종 + 패턴 5종) → 유형 판정(투자사기/대출사기/가상자산) → 확인 대상·조회 경로 매핑 |
| 생성형 AI 보조 레이어 | Netlify Functions(`analyze.js`)로 Google Gemini API 호출, 상황 요약과 유형 보정만 수행 |
| 정적 데이터 | 금감원 소비자경보 198건 기반 JSON 6종(2절 참고) |
| 검증용 캐시 | 시나리오 3종의 AI 응답을 사전 생성해 저장, API 호출 없이 즉시 표시 |

**명시적으로 제외한 것**: 로그인, 데이터베이스, 실시간 조회 API 연동, 알림, 파일 업로드, 다국어.

## 3. 사용자 이용 흐름

### 검증 시나리오 버튼 경로

1. 배포 URL 접속
2. "예시로 보기"의 투자사기·대출사기·가상자산 버튼 중 하나 클릭 → 입력창에 시나리오 문구 자동 입력
3. "확인하기" 클릭
4. 규칙 엔진이 즉시 실행되어 감지된 위험 신호 → 유형 판정 → 확인해야 할 것 → 유사 경보 사례 → 확인 후 조치가 한 번에 표시됨
5. 입력 문구가 캐시된 시나리오와 정확히 일치하므로, API 호출 없이 사전 생성된 AI 요약이 "사전 생성된 예시 응답" 배지와 함께 즉시 표시됨

### 자유 입력 경로

1. 배포 URL 접속
2. 입력창에 상황을 직접 서술해 입력
3. "확인하기" 클릭
4. **분기 A — 범위 밖 판단**: 입력이 부동산 매매·분양 등 비금융 거래로 판단되면(펀드·신탁 등 금융상품 문구가 없는 경우) 결과 섹션은 표시되지 않고 범위 밖 안내 문구만 나타난다. 여기서 흐름 종료.
   **분기 B — 정상 판정**: 그 외의 경우 규칙 엔진이 실행되어 감지된 위험 신호 → 유형 판정(또는 미확정 시 3개 유형 전체) → 확인해야 할 것 → 유사 경보 사례 → 확인 후 조치가 표시된다.
5. (분기 B 계속) 입력 길이가 20자 미만이면 AI를 호출하지 않고 여기서 종료된다. 20자 이상이면 상황 요약 영역에 로딩 문구가 뜨고 AI 함수를 호출한다.
6. AI 응답 결과에 따라 갈린다.
   - 성공: 1~2문장 상황 요약이 표시되고, AI가 유형 보정을 확신한 경우에만 보정 안내가 추가로 표시된다.
   - 할당량 초과(HTTP 429): 회색 작은 글씨로 "AI 요약은 일시적으로 제공되지 않습니다"만 표시된다.
   - 그 외 실패(키 없음, 네트워크 오류, 타임아웃, 형식 오류): 상황 요약 영역이 조용히 빈 채로 유지되고, 에러 메시지는 표시되지 않는다.
7. "확인하기"를 같은 문장으로 다시 누르면 세션 내 캐시된 이전 AI 응답이 재호출 없이 즉시 표시된다.

## 4. AI 및 데이터 처리 방식

### (1) AI가 수행하는 역할

- **모델**: `gemini-3.1-flash-lite` (`netlify/functions/analyze.js`의 `GEMINI_MODEL` 상수)
- **하는 것**: (1) 자유서술 상황을 1~2문장으로 요약 (2) 규칙 기반 유형 판정에 대한 보정(확신이 없으면 규칙 결과를 그대로 유지)
- **하지 않는 것**: URL·메뉴 경로 생성, 건수·비율 계산, 확인 대상 신설, 확인 근거 문장("왜 확인해야 하나") 생성 — 이 문장은 확인 대상별로 미리 정해둔 법령 근거를 끼워 넣는 정적 템플릿이며 AI가 만들지 않는다.
- 규칙 기반 판정이 항상 먼저 실행되어 화면에 표시되고, AI는 그 위에 별도로 얹히는 보조 레이어다. AI 호출이 실패하거나 응답하지 않아도 규칙 기반 결과(신호·유형·확인 카드·유사 사례·확인 후 조치)는 그대로 유지된다.

### (3) 입력·출력 데이터

- **입력**: 사용자가 입력창에 작성한 텍스트
- **Functions(`/.netlify/functions/analyze`)로 전달되는 것**: 입력 텍스트 원문, 규칙 판정 결과(유형, 감지된 신호 목록, 제시된 확인 대상 목록)
- **출력**: 1~2문장 상황 요약, 보정 여부(boolean)와 보정된 유형(해당 시), 보정 근거 문장(해당 시)

### (4) 개인정보·민감정보 처리 여부

- 로그인·회원가입 기능 없음
- 데이터베이스 없음. 사용자 입력 텍스트를 서버에 저장하지 않음(요청 처리 후 즉시 소멸)
- 쿠키·트래킹 스크립트 없음(코드에 `localStorage`, `sessionStorage`, `document.cookie` 사용 없음을 확인)
- **입력 텍스트는 상황 요약·유형 보정을 위해 Google Gemini API(외부 서비스)로 전송된다.** 20자 미만이거나 검증 시나리오와 일치하는 입력은 전송되지 않는다.
- 사용자가 계좌번호·주민등록번호 등 개인정보를 입력하지 않도록, 입력창 바로 아래에 "입력 내용은 상황 요약을 위해 외부 AI 서비스(Google Gemini)로 전송됩니다. 계좌번호·주민등록번호 등 개인정보는 입력하지 마세요." 안내 문구를 상시 표시한다.

## 5. MVP 검증 방법

### (1) 확인 절차

1. 배포 URL 접속
2. 입력창 아래 "예시로 보기"의 투자사기·대출사기·가상자산 버튼 중 하나를 클릭한다 — 이 경로는 AI 할당량과 무관하게 항상 동작한다(사전 생성된 응답을 사용하므로 API 키가 없거나 할당량이 소진돼도 정상 표시된다).
3. "확인하기"를 클릭하면 감지된 위험 신호, 유형 판정, 확인해야 할 것, 유사 경보 사례, 확인 후 조치, 상황 요약이 순서대로 표시된다.
4. 나머지 두 버튼도 같은 방식으로 확인한다.
5. 자유 입력을 원하면 입력창에 직접 상황을 서술하고 "확인하기"를 클릭한다. 20자 이상이면 AI 상황 요약이 별도로 추가된다(API 키·할당량 상태에 따라 표시되지 않을 수 있으며, 이 경우에도 규칙 기반 결과는 정상 표시된다).

### (2) 샘플 입력값과 예상 결과

아래 5건은 배포된 사이트(https://scintillating-bienenstitch-52854d.netlify.app)에서 실제로 실행해 확인한 결과다.

| 입력 | 판정 유형 | 감지 신호 | 확인 카드 수 |
|---|---|---|---|
| (버튼) 투자사기 시나리오 — "유튜브 보다가 몽골 은행 채권을 연 11% 준다고 해서 알아보고 있는데, 국내 증권사가 아니라 처음 보는 곳에서 판매한다고 합니다..." | 투자사기 | 고수익, SNS, 무인가 | 2 |
| (버튼) 대출사기 시나리오 — "대출 상담해준다는 사람이 신용 확인 겸 먼저 30만원을 빌려서 일주일 뒤에 40만원을 갚으라고 합니다..." | 대출사기 | 단기 고금리, 선입금 요구(패턴 신호) | 2 |
| (버튼) 가상자산 시나리오 — "예전에 쓰던 코인 거래소가 곧 문을 닫는다며, 지금 안 옮기면 보유 코인이 소각된다는 문자를 받았습니다..." | 가상자산 | 영업종료 사칭, 가상자산 소각 빙자, 링크 유도(패턴 신호) | 1 |
| 자유 입력 — "친구가 이 코인 지금 사면 무조건 2배 오른다고 해서 급하게 입금하려고 하는데 괜찮을까요?" | 가상자산 | 수익보장 | 1 |
| 자유 입력 — "대부업체 직원을 사칭한 사람이 전화로 대출을 권유하며 신용 확인을 요구했습니다." | 대출사기 (배타적 키워드 "대출"로 확정) | 사칭 | 2 |

참고로 "김해에 부동산 투자하면 무조건 200% 수익이래"를 입력하면 위 판정 흐름 대신 서비스 범위 밖 안내 문구가 표시되는 것도 확인했다(펀드·신탁 등 금융상품 문구가 없는 순수 부동산 거래로 판단).

### (3) 실행 환경 / 브라우저 제한사항

- 로컬 개발 서버(Netlify Functions 로컬 실행, `netlify dev`)와 배포된 사이트 양쪽에서 Playwright 기반 Chromium으로 실행해 확인했다. 다른 브라우저(Safari, Firefox 등)에서의 별도 테스트는 수행하지 않았다.
- 모바일 대응: 뷰포트 375×812(모바일 화면 크기)로 확인한 결과 가로 스크롤 없이 정상 렌더링됐다. 별도의 모바일 전용 CSS 미디어쿼리는 없으며, 최대 폭 640px의 단일 컬럼 유동형 레이아웃으로 화면 크기에 맞춰 자연스럽게 줄어드는 방식이다. 실제 모바일 기기(스마트폰)에서 투자사기 시나리오로 접속해 확인했다. 가로 스크롤 없이 정상 렌더링되었고, 확인 후 조치·유사 경보 사례를 포함한 전체 결과 화면이 깨짐 없이 표시됨을 확인했다.

### (4) MVP 단계의 제한사항

- 조회는 대행하지 않으며, 실제로 정상 접속을 확인한 URL로 연결하는 경로 안내만 제공한다.
- 데이터(경보 198건, 위험 신호 23종 등)는 2026년 9월 기준 스냅샷이며 자동 갱신되지 않는다. 신규 경보가 발령돼도 반영되지 않는다.
- 가상자산사업자 신고 여부 확인 경로는 정확한 URL을 확보하지 못해, 탐색 절차(사이트 접속 → 메뉴 이동 → 게시물 확인)로 안내한다.
- 유형 판정 정확도가 유형별로 균일하지 않다(경보 제목 55건 측정 기준: 투자사기 88.6%, 대출사기 100%, 가상자산 20%). 가상자산 유형은 "사칭" 신호가 투자사기 쪽에 크게 쏠려 있고 이를 구분할 배타적 키워드가 데이터에 없어, 이번 개선으로도 해결하지 못했다.
- AI 상황 요약은 무료 할당량 초과 시 제공되지 않으나, 규칙 기반 결과(신호·유형·확인 카드·유사 사례·확인 후 조치)는 이 경우에도 정상 표시된다.
- 다루는 유형이 투자사기·대출사기·가상자산 3종으로 한정된다. 경보 198건 중 보이스피싱·보험·기타 유형(163건)은 이 서비스의 판정 범위에 포함되지 않는다.
- 서비스 범위 밖 안내는 부동산 관련 규칙 1개만 구현돼 있다. 그 외 비금융 사안(예: 중고거래 사기 등)은 범위 밖으로 안내되지 않고 3개 금융 유형 중 하나로 억지 판정될 수 있다.
- 확인 후 조치의 담당부서 연락처는 유형별 최근 경보 1건에서만 가져온 것으로, 경보마다 담당부서가 다를 수 있다는 점을 화면에도 명시하고 있다.
